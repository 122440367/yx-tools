## Why

yx-tools 已支持多种测速结果上传方式，但自动化任务结束后缺少简洁的飞书执行通知；同时，CLI 参数较多，用户需要手工查阅文档和拼接命令，容易遗漏必填项或写错参数。增加飞书任务通知和面向 GitHub Pages 的静态命令生成器，可以降低自动化测速、上传与状态确认的门槛。

## What Changes

- 新增独立的飞书企业自建应用机器人通知通道，通过 App ID、App Secret 获取 tenant access token，并在任务结束时把执行摘要发送到指定接收目标。
- 飞书接收目标支持 `chat_id`、`open_id`、`union_id`、`user_id` 和 `email` 等多种 `receive_id_type`，对凭据、接收类型和接收 ID 进行校验。
- 飞书消息只包含任务类型、成功/失败、总耗时、测速结果数量和可选上传目标/状态等摘要，不包含 IP、端口或逐条测速明细。
- 摘要使用纯文本和单一接收目标，包含本地时区的开始/结束时间、耗时、测速结果数量、上传目标/数量及最多约 300 字符的脱敏失败原因。
- 在 `test` 与独立 `upload` 流程中支持显式 `-notify feishu`；通知配置与 `-upload` 独立，使现有上传目标和飞书通知可以同时启用，并覆盖成功、失败和用户取消三种结局。
- 通知失败会使整体命令返回非零；临时错误采用总预算 10 秒、最多两次的有限重试，并使用幂等标识避免重复通知。用户取消时使用独立的 5 秒上下文尝试发送“已取消”摘要。
- **BREAKING**：`yx test` 正常结束但得到 0 条有效结果时改为失败并返回非零；测速成功但结果上传失败时，总状态也为失败，同时保留分阶段状态。
- App Secret 必须在每次启用飞书通知时通过 CLI 参数提供，不写入 `yx-config.json`；其他非秘密飞书目标配置在通知成功后保存复用。
- 新增可由 GitHub Pages 托管的纯静态 `yx test` 命令生成器，按测速、输入源和上报方式分组展示参数，提供条件字段、即时校验、命令预览和一键复制。
- 命令生成器提供简体中文单行命令，支持 POSIX 与 PowerShell，并按系统/架构生成 `./yx_linux_arm64`、`./yx_darwin_amd64`、`.\yx_windows_amd64.exe` 等发布文件名；只输出偏离默认值或主动启用的参数。
- 命令生成器支持现有结果上传目标和独立飞书通知配置，但不联网提交、不保存任何表单状态、不写入 URL；敏感值在预览中默认遮罩，复制时仍使用真实值，并提供显式显示开关和 shell 历史警告。
- 更新 CLI 帮助和 README，说明飞书应用权限、接收目标获取方式、凭据保护及 GitHub Pages 使用入口。

## Capabilities

### New Capabilities

- `feishu-task-notification`: 使用飞书企业自建应用凭据向一种选定类型的接收目标推送任务执行摘要，并与现有 CLI 测速、上传和非秘密本地配置集成。
- `test-command-generator`: 通过 GitHub Pages 上的纯静态表单生成、校验并复制可执行的 `yx test` 命令。

### Modified Capabilities

无。

## Impact

- 影响 `cmd/yx/main.go` 的通知参数、帮助文本、任务结果汇总和退出路径；现有上传模式保持兼容。
- 影响 `internal/app/config.go`，并新增或扩展通知模块来承载飞书配置、鉴权、摘要消息构造和发送逻辑。
- 新增飞书 HTTP 单元测试、任务成功/失败通知测试、CLI 参数/配置测试，以及静态命令生成器的生成与安全行为测试。
- 在 `docs/` 下增加 GitHub Pages 静态资源，并更新 README；不需要新的前端框架或 Go 运行时依赖。
- 运行时新增对飞书开放平台 HTTPS API 的访问；App Secret 不落盘，但会进入用户主动复制的命令、shell 历史和进程参数，因此文档与 UI 必须明确风险。
